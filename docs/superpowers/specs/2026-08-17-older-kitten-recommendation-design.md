# Fuluck 较大月龄猫推荐展示设计

日期：2026-08-17
状态：已获 Owner 方向确认，等待书面规格复核
范围：Fuluck 网站与网站 API；Koneko 永久只读

## 目标

把较大月龄在售猫长期显示的 `NEW` 改成正向、可信的推荐展示，解释这类猫的实际优势，同时不把月龄自动推断为“成猫”“已绝育”“性格稳定”或“更容易适应”。

本次成功标准：

1. 当前 7 只较大月龄且 `available` 的猫不再显示 `NEW`，改为现有三语推荐标签 `おすすめ / Featured / 推荐`。
2. 当前 2 只较大月龄且 `reserved` 的猫只移除 `NEW`，不作为可售推荐置顶。
3. 推荐猫详情页显示一段网站自有的三语说明，解释“体格和日常习惯更容易观察、可更从容确认家庭适配”，不改写 Koneko 镜像介绍。
4. 只有已有明确来源记录的 `2604-02563` 继续显示其现有“去勢済み／已绝育／Neutered”事实；其他猫不生成绝育结论。
5. 首页、列表页、动态卡片、详情页和弹窗不出现互相矛盾的 `NEW`/推荐状态。

## 选定方案

### 1. 复用现有推荐字段

不增加新的推广枚举。对 7 只 available 猫逐只写入：

```json
{
  "isNew": false,
  "promotionTag": "featured",
  "promotionPriority": 0
}
```

现有共享目录契约已经把 `featured` 翻译为：

- 日文：`おすすめ`
- 英文：`Featured`
- 中文：`推荐`

`promotionPriority=0` 表示这 7 只作为同一推荐组，不制造“仅剩”“限时”或虚假稀缺。现有目录排序会把推荐组放在普通在售猫之前，组内继续使用既有稳定排序。

对两只 reserved 猫只写入：

```json
{
  "isNew": false
}
```

### 2. 推荐标签的展示位置

- 首页与列表卡：继续使用现有卡片正文里的推荐 chip；右上角不再出现 `NEW`。
- 详情页：在状态行追加相同语言的推荐 chip，确保从列表进入详情后语义连续。
- 动态卡片与静态生成结果使用同一个 `kitten-catalog.js` 标签契约，不复制另一套翻译。
- 弹窗读取卡片的 `promotionTag` 并显示推荐 chip；不再仅依赖 `data-new`。

### 3. 详情页推荐说明

仅当 `promotionTag === "featured"` 时，在基本资料表之后、Koneko 个体介绍之前显示网站自有说明。

日文：

> **月齢を重ねた子の魅力**
>
> 月齢を重ねた子は、体格や日々の過ごし方を実際に見ながら、ご家庭との相性をゆっくり確かめていただけます。現在の性格や生活リズムは、下の個体紹介をご覧ください。

中文：

> **月龄较大猫咪的优势**
>
> 月龄较大的猫，体型和日常习惯更容易通过实际观察来了解，您可以更从容地确认它与家庭生活是否合适。每只猫当前的性格与生活节奏，请查看下方个体介绍。

英文：

> **Why an older kitten can be a great fit**
>
> With an older kitten, their build and daily routines are easier to observe, giving families more time to consider the fit. See the individual profile below for current details.

这段说明只陈述“更容易观察与确认”，不承诺性格、健康、适应速度或成交结果。

### 4. 绝育事实

本次不从年龄、性别或自由文本自动推断绝育状态，也不新增全体绝育标签。

`2604-02563` 的 Koneko 镜像短备注和详情介绍已经明确包含 `去勢済み／已绝育／Neutered`，本次保留其现有展示；其他 6 只的绝育状态视为未知，不显示“未绝育”或“已绝育”。未来若要把绝育做成独立标签，应另行增加经过人工核验的结构化字段和证据时间，不能解析自由文本生成。

## 数据与发布边界

- 不登录、不编辑、不提交 Koneko。
- 不修改 `note/noteZh/noteEn` 或 `description/descriptionZh/descriptionEn`；这些是 Koneko 单向镜像字段。
- 网站展示代码可以读取 `promotionTag`，但不能反向写 Koneko。
- 生产数据写入前保存当前 API 快照和 9 只目标记录的原值；只使用逐只 `PUT`，禁止 `/bulk`。
- 每次写入后立即读回并核对 `breederId/status/birthday/price` 未被连带修改。
- 代码先在独立分支完成测试；部署和数据写入均需使用 Owner 已明确给出的“只改网站”授权。

## 测试设计

实施遵循测试先行：

1. 先增加生成器测试，证明 featured 详情页必须出现本语言推荐标签和说明，普通猫不得出现。
2. 先增加动态展示测试，证明 featured 卡片/弹窗显示推荐，`isNew=false` 不显示 `NEW`。
3. 运行聚焦测试，确认新增测试在实现前因缺少推荐详情展示而失败。
4. 完成最小实现后运行完整 `node --test tests/*.test.js`。
5. 运行 `node tools/verify-generated.js`、`git diff --check` 和 Worker dry run。
6. 部署后核对三语列表与至少三只代表页：最老猫 `2605-02526`、已去势猫 `2604-02563`、较大月龄幼猫 `2603-02736`。
7. 生产 API 验收：7 只 available 为 `isNew=false + featured`；2 只 reserved 为 `isNew=false`；其他猫字段不变。

## 失败与回滚

- 任一 API 写入出现非目标字段变化：停止后续写入，使用备份逐只恢复目标字段。
- 三语任一页面出现错语、重复标签、`NEW` 与推荐并存：不部署或立即回滚代码提交。
- Koneko 新鲜状态显示猫只已售或状态变化：以 Koneko 为准，从本次目标集移除，不强行推荐。
- 推荐说明与个体事实冲突：移除通用说明，不覆盖 Koneko 原文。
- 回滚数据只恢复本次修改的 `isNew/promotionTag/promotionPriority`，不得整表覆盖。

## 明确不做

- 不改价格、销售状态、猫只生日、健康、疫苗、芯片或绝育事实。
- 不把 D150/D180 写成“成猫”定义。
- 不新增“清仓、特价、最后机会、滞销、大龄猫、老猫”等标签。
- 不重写七只猫的 Koneko 原始长介绍。
- 不使用 AI 图替换真实猫照片。
